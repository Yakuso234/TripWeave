# 休息、实际出发和到达时间

2026-11-17。原Stop.start_time/end_time已表示本站开始、结束，原程序按上一站结束加地图耗时判断衔接；站间留白中具体休息、实际出发藏在文字时无法参与这项计算。本轮增加Stop.transfer，不替模型移动站点。

```json
{
  "day": 1,
  "place_id": "已核实的下一站地点ID",
  "start_time": "18:30",
  "end_time": "19:30",
  "kind": "meal",
  "reason": "附近自选正餐，实际供应待核实",
  "transfer": {
    "departure_time": "17:40",
    "arrival_time": "18:16",
    "rest_before": [{"start_time": "15:20", "end_time": "17:40"}],
    "rest_after": [],
    "buffer_minutes": 10
  }
}
```

这是衔接结构示例，不是真实行程。休息位置绑定本段起终点：rest_before在上一站地点（首段在当日起点），rest_after在本站地点。去其他地点休息需要明确该地点与相应衔接，不把交通塞进休息。departure_time是实际拟定出发，arrival_time是实际拟定到达，本站start_time是开始参观/用餐等，不混用三个概念。

## 硬检查

- 实际出发不得早于上一站结束，首站明确锁定的最早出发时间仍遵守。
- 出发前休息须在上一站结束后且实际出发前，不能重叠；首段出发前休息可以早于期望出发时刻，出发锁定约束的是实际出发。
- 拟到达不得早于实际出发加真实地图耗时。17:40→18:00只有20分钟，地图需36分钟时，返回transfer_duration及所缺16分钟。
- 到达后休息须在实际可到达之后、本站开始之前，不能与交通或其他休息重叠。
- 本站最早可开始为“拟到达与到达后最后一段休息结束的较晚者＋额外buffer_minutes”。缓冲独立预留，不能重复占用休息。
- 例中休息至17:40、地图36分钟、额外缓冲10分钟，最早18:26开始；若本站18:00开始，connection返回day/站序/地点、出发、地图耗时、可用/所需分钟、差额、最早到达及最早可开始时间。

地图交通累计仍只统计地图分钟，休息和额外缓冲不计交通目标；游玩指标也不计这些休息。模型决定取舍，程序只查合法性；原有完整草稿回流、局部修订和全量复核保留。草稿重复检测及范围保护包含transfer，不能只改休息就被当作原稿无变化。

酒店end_time在提示词中明确为办理入住/当天活动收尾，不以23:59表示整夜住宿；过夜仍由hotel_nights和酒店收尾表达。未新增checkout或订房能力。

## 保存、展示与边界

transfer随草稿/最终候选JSON保存SQLite和执行记录，前端显示实际出发→到达、出发前/到达后休息及缓冲。旧记录缺transfer时保持原JSON形状，不伪造时间；只沿用站间空档检查。

新提示词要求填写transfer，并让说明引用同一组字段。结果timing_coverage披露实际填写站数；未填时页面提示只能检查空档，不能把备注休息说成已验证。当前仍不自动抽取任意自然语言时刻，也不能保证模型不会另写矛盾文字；Reviewer被要求检查明确休息是否确实落入字段，覆盖不足不冒充全面核对。字段可选是旧记录兼容设计，未新增“覆盖不足自动阻止接受”的门禁。

本轮无新框架、数据库表、Agent或真实调用，8轮/300秒和模型强度/输出预算不变。离线验证见[QA](evaluations/V02_QA.md)，源码字段见[domain.py](../tripweave/domain.py)，算法见[real_planner.py](../tripweave/real_planner.py)，当前模型提示词见[PROMPTS_CURRENT](PROMPTS_CURRENT.md)。
