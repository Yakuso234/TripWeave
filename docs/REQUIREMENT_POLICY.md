# 期望目标与不可突破要求

更新：2026-11-17。依据用户确认：普通时间、节奏和金额目标可结合体验权衡；固定景点、预约和明确不可突破条件优先。本单元没有增加Agent、模型调用阶段或真实API测试，8轮/180秒等预算不变。

## 表单与含义

整趟金额、每间每晚住宿金额均展示为“期望金额”，不是实价、最高费用或已满足预算的承诺。三步偏好页都展示同一个“额外要求与不可突破条件”文本框，换步骤保留内容，保存时仍用notes随需求入SQLite。长期偏好用custom_pace提供长期额外要求，修改页的revision_request可说明必须保留、禁止或不可突破的内容。本次明确要求优先于普通或长期偏好。

| 项目 | 新规划默认语义 | 不可突破的情况 |
| --- | --- | --- |
| 每日景点数量 | 期望目标，同地点分段计1个 | 显式锁定max_attractions，或文本明确禁止超出 |
| 每日游玩分钟 | 期望目标，按实际参观段累计 | 显式锁定max_sightseeing_minutes，或文本明确限制 |
| 游玩时间占比 | 期望目标，原始期望窗口作为固定分母 | 显式锁定max_sightseeing_ratio，或文本明确限制 |
| 每日地图交通分钟 | 期望目标，首段及回酒店计入，缓冲另留 | 显式锁定max_transport_minutes，或文本明确限制 |
| 每日期望出发、结束 | 可解释提前出发或晚结束 | 锁定start_time表示不得提前，end_time表示不得晚于；真实预约、车次或明确截止仍须遵守 |
| 期望金额 | 超出估算预留提示，不直接否决 | 文本明确最高金额须由模型优先核对；价格未知不能承诺满足 |
| 明确必去、已选景点、手选酒店 | 必须保留 | 不能为凑普通目标自行删除或替换 |
| 景点时间要求、固定预约 | 必须满足所填窗口、停留或精确场次 | 页面明确此处为锁定要求；大致游玩时间写额外要求 |
| 时间衔接、站点重叠 | 仍为程序检查 | 普通交通总时长放宽不能允许实际路段赶不上 |
| 开放、价格等资料未知 | 信息缺口 | 不因为目标是软的，就把未知包装成已确认 |

不靠关键词“绝对/一定”机械匹配：如“不坐出租车”同样是明确限制。没有自动将自由文本全部编译成程序硬约束；文字条件由规划与Reviewer语义检查，不能宣传任意自然语言都已被确定性保证。对于目前有对应数值控件的严格条件，可勾“此项不可调整”获得程序检查；其他条件仍有这一能力边界。

## 数据与路由

保留已有max_*、budget_total、hotel_budget字段名兼容已有记录，更新含义说明。新增strict_preferences白名单，只允许四项数值与start_time/end_time，不允许借此变更工具权限或系统预算。空数值不设目标，0保持有效。

daily_metrics继续保存实际值、原窗口、目标值，并带preference_policy=soft_targets_v1与strict_preferences。pacing_issues分类：明确锁定超限仍为draft_error；普通偏离为preference_deviation/warning。validate只用硬错误阻断，仍检查真实衔接、固定预约、必去、酒店身份和事实覆盖。出发软目标不再被用于证明用户预约必然赶不上；固定预约之间的交通必要条件仍检查。

普通偏离、需要提前出发/延后结束、估算预留超过期望金额，保存在候选preference_deviations中并交Reviewer，页面单独展示“与期望目标的差异”。不会为每项warning单独多调用Agent，也不由程序搬站、删景点或决定体验取舍。Reviewer仍可基于具体体验问题提出意见，不能把合理数值偏离机械判失败；ready仍须通过其既有初审/协商与版本接受门。

旧候选保留原快照和错误，不改写历史结果或让旧失败记录自动变ready。新记录显示实际/期望并标出锁定项，缺新策略字段的旧记录仍显示原实际/上限。旧需求再次生成采用新语义，额外文本和已明确锁定要求仍需保留。

## 提示词与成本边界

REQUIREMENT_POLICY由排程和Reviewer共用，明确硬要求、软目标、信息缺口；规划提示词按身份、计量、时间、正餐、资料分段，清理旧的“所有数值都必须满足”表述。偏离时要求在summary说明期望/实际、具体原因及收益，不能只说体验更好；不为轻微偏离强行重排。保留完整草稿、明确查询清单、局部修订参考全程、交通20→总30/60→总80的缓冲例子与必需资料补查边界。

固定规划正文由上版3380字符缩减至2624字符；是Unicode字符数量，不是供应商tokens或费用测量。输出合同未增加解释工具、额外Agent或前置模型轮次。离线SDK模拟验证普通偏离可沿首稿→证据修订→Reviewer正常3次响应路径，不额外触发业务重排；不能据此宣称真实成功率提高、时延降低或费用减少。提示词原文见[PROMPTS_CURRENT](PROMPTS_CURRENT.md)，具体检查见[QA](evaluations/V02_QA.md)。
