# 资料核检与一次恢复

更新：2026-11-15。已有代码与离线HTTP模拟验证；本单元无真实供应商请求。研究与排程、校验共享8轮模型调用/180秒，地图预算不变，不新增Agent、框架或中间件。

## 当前链路

1. 排程通过`PlanningInformationRequest`说明地点、旅行day、字段、已有资料、关联用户要求/拟安排时段与为什么未知会影响规划。多个字段逐项解释，不为丰富介绍无条件补查。
2. 研究只查这些地点/日期，程序提供日期及ISO weekday；按字段返回`found/unknown`。未知增加`unknown_reason/unknown_detail`，兼容旧合同但漏原因会显式记录为模型未说明，不能称资料不存在。
3. `research_evidence.validate_evidence`将提议绑定实际来源、连续引文、显式日期和钟点；输出逐字段`diagnostics`，包含地点/day/date/field、阶段、code、origin、severity、具体原因及必要的期望/实际值。
4. 有额度时最多恢复一次：引用/提取问题复用已有来源重提取；空结果、不相关、摘要不足、字段未写、日期不适用、来源冲突、连接或超时，按失败字段改关键词补查再提取。新旧来源均提供给模型核对，不能因为新结果更合意就消除矛盾。HTTP权限/限流或错误格式不盲目重发。
5. 恢复只合并失败字段，保留原已通过字段。所有搜索合计最多5次，模型工具往返及格式重试计入同一个预算。恢复前至少预留再次排程与初审所需的2次模型请求；这不保证额外工具或协商一定够用。额度不足是`incomplete`，接口故障是`service_error`。
6. 完成或仍未知的研究结果在剩余额度允许时交回排程一次，带`planning_facts/research_feedback`。模型可以调整普通可选安排，不能删除手选、必去或固定预约。若实际行程仍使用缺少关键事实的地点/日期，则保留草稿并返回`needs_information`；再请求研究不启动第二阶段或无界循环。
7. 程序业务检查和独立校验Agent继续执行；没有可信时间不能因为两个模型认同而标为可用。

## 放宽的边界

- 引文允许空格、换行等空白差异，匹配后保存来源中的真实原文片段，保留原文偏移映射；不做改字、改数值、改标点、相似度猜测或跨不相关片段拼接。时间核对仍用来源实际片段。
- 多个引用中部分不支持引文时，仅保留真正支持的引用，移除无效或不支持的编号并记录warning。至少一个实际来源必须支持完整引文，不把无依据内容算作已知。
- 程序只检查证据连接和有限结构，不证明原文权威、语义必然正确、星期规则完全适用或未来一定开放。闭馆语义、日期范围、节假日例外仍有能力边界。
- `origin=model`是研究Agent对内容不相关/摘要不足/来源矛盾等的判断，不冒充程序已证明。只见摘要不能断言完整官网或整个互联网没有资料。

## 诊断与恢复示例

| code/情况 | 行为 |
| --- | --- |
| `field_missing/field_duplicated` | 漏回或重复字段，针对该字段重提取 |
| `source_id_invalid/quote_not_in_source` | 全部引用无效或引文没有实际依据，带明确编号问题重新提取 |
| `opening_time_not_in_quote/admission_time_not_in_quote` | 记录具体无依据钟点，不采用该时间结构，交研究纠正 |
| `opening_structure_missing/admission_structure_missing` | 有文字但缺少可计算结构，重新提取；仍不足则保持缺口 |
| `search_empty` | 改关键词一次；不是声称全网无资料 |
| `content_unrelated/excerpt_insufficient/field_not_stated/sources_conflict/date_not_applicable` | 模型具体解释，程序针对缺字段补搜一次，再由模型判断 |
| `search_timeout/search_connection_error` | 有剩余额度时一次恢复，保留初次失败诊断 |
| `search_http_error/search_response_format/search_sources_format` | 明确服务错误和可获得的HTTP状态，不把错误响应当空资料；不自动盲重发 |
| `model_unknown_unspecified` | 记录“模型未解释未知”，不凭空猜原因；将缺口带回排程判断 |
| 请求/搜索预算不足 | `incomplete`，保留事实与诊断；不称模型分歧或需求无解 |

## 保存、页面与验证

`research_requests`保存原补查原因/问题，`research_diagnostics`保存具体核检、恢复轮次与是否已解决，随候选JSON进入SQLite。未解决issue附对应诊断，前端摘要和可展开“资料补查记录”区分程序检测/研究判断，所有文本转义；旧记录没有诊断不补造。正常返回或捕获异常可回看，进程突然中断仍不是checkpoint恢复。

已通过358项Python、4项PostgreSQL因无环境跳过、44项Node；新增17项Python与2项前端回归。验证连续引用的宽容/拒绝边界、诊断位置、保留字段、按因重提取/补搜、预算与总搜索上限、超时恢复、未知回规划和硬要求、SQLite回读及HTML转义。HTTP模拟不能证明真实搜索覆盖、提示词质量或费用降低。

当前仍使用搜索返回的有限摘要，未新增网页正文读取工具或供应商，也未放宽所有未知字段的业务必要性判断；必要性主要由排程提示词约束，尚无完整自由文本依赖分析。真实联调和更细的必要性分级待后续讨论。


2026-11-16经用户确认：默认实验预算调整为180秒、8轮，思考强度和单次输出上限不变。轮次按SDK已进入历史的模型响应计数，工具执行本身不占模型轮次；读取工具结果继续推理会产生下一轮。HTTP尝试另行记录，不能把轮次限额当绝对费用上限。旧候选保留当时6轮/90秒快照。

## 2026-11-19 按字段限制定向搜索

本节更新上文第 4–6 步及预算口径。三类 Agent 共享 600 秒的整轮截止时间。研究仍可按新缺口多轮进入，每批最多 5 个搜索 HTTP 请求。

- `reservation_channel` 指预约入口和方式，`reservation_requirement` 指计划日期是否必须预约，`ticket_availability` 指余票或可预约名额。入口存在不能证明必约或有票。当前缺实时库存接口，余票请求直接提示去官方渠道确认，无网页搜索。旧候选保留 `reservation_rules` 标签。
- 一轮规划内，每个地点 ID、旅行日期和字段最多 2 次实际网页搜索。研究内部改关键词重查共用计数，HTTP 请求失败或超时计入，重提取和缓存复用不计。混合批次只搜索仍有次数的字段，关键词由这些字段生成。
- 排程收到 `research_limits`、现有资料和诊断后作取舍。可替换依赖未确认资料的可选景点。必去地点仍保留并说明待确认事项，依赖关键资料的候选继续显示待补查。若排程收到拦截反馈后仅重复索取拦截字段，保留草稿和证据并停止补查。
- 计数在本次运行内有效。候选和页面保留字段及拦截原因。离线 SDK 和 HTTP 模拟覆盖换问法、内部恢复、混合字段和跳过余票检索。
