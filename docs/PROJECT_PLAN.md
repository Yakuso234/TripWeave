# TripWeave 当前初版规划

更新：2026-11-07，Asia/Singapore。本文件替代初版离线范围；原构思保留在 PROJECT_PLAN_BASELINE_20261105.md，历史验证保留 PROTOTYPE_QA.md。

## 目标

面向中国大陆校招 Agent 应用工程，SW 承担 Java 后端主项目。用户授权助手设计实现，再由用户审阅。最新要求是实际根据输入和接口结果规划，内容包含住宿、餐饮与交通，界面采用顶部页面与分步偏好；DeepSeek 默认，凭据稍后提供。不能把固定输出当作产品功能。

## 本轮交付范围

1. 单城市 1–3 天：结构化需求、真实地点、住宿位置推荐/手选、固定预约、用餐、路线与时间校验。
2. 两种路径：高德＋基础排程，以及高德＋DeepSeek。无 Key 显式阻止；失败无固定数据回退。基础模式不假装理解所有自由文本。
3. 五页工作台：概览、偏好、住宿、每日安排、接入设置；近期旅行和候选历史；接受与过时版本提示。
4. 数据归属：SQLite 本地默认；SQLAlchemy Core 提供 PostgreSQL 可选适配。需求更新、候选、接受事件入库；并发写冲突拒绝，不覆盖其他请求。
5. 验证并同步选型、启动、限制与本地记忆。HTTP 模拟与真实 API 测试分别标记。

## 验收主线

填写两天偏好 → 查询真实酒店 → 生成每天安排 → 检查预约和交通 → 接受 → 晚出门重新规划 → 旧候选不能覆盖新版本 → 刷新恢复，历史可查看。

没有凭据时可以完成界面、代码、HTTP 合同与数据库测试；真实模型、真实高德、真实完整端到端保持待验证。房价、空房与营业信息缺失不能用预算上限替代事实。

## 中间件决策

SQLite 已足够支撑当前单人本地阶段。PostgreSQL 为后续部署和多个规划请求并发准备适配，只有真实环境通过后才标记验证通过。不引入 Redis、消息队列、向量库、多 Agent 或任务引擎；后续出现缓存命中数据、后台可靠任务或资料检索需求时另做决策。依据见 ADR-002，部署前提见 DEPLOYMENT.md。
